# `main.py`

Is the entry point of the application that initializes CixerQuiz. This module contains the main execution logic required to start the graphical user interface and establish the initial connection with all application components, including configuration management and resource loading.

# `poetry.lock`

Is a dependency lock file generated by Poetry that ensures consistent versions of installed packages across different installations. This file guarantees reproducibility and stability of the development and production environments by pinning exact versions of all direct and transitive dependencies.

# `pyproject.toml`

Is the project configuration file for Poetry that defines project metadata, dependencies, development dependencies, and build configuration. This file serves as the primary configuration manifest for the entire project structure and its required runtime environment.

# `README.md`

Is the primary documentation file of the project that provides general information, installation instructions, usage guidelines, and an overview of CixerQuiz. This markdown file serves as the main entry point for new users and developers and users seeking to understand the project's purpose and functionality.

## assets

Is a container directory that stores all multimedia resources and visual assets used throughout the application, including backgrounds, branding elements, icons, music files, stylesheets, and sound effects.

### backgrounds

Is a subdirectory containing SVG background graphics used in the user interface.

### branding

Is a subdirectory that contains all brand identity resources for the project. This includes logos, theme variations, and visual identity elements.

### icons

Is a subdirectory containing SVG icon files used throughout the application interface. These scalable vector icons represent actions and states such as file operations, user interactions, and navigation elements.

### music

Is a subdirectory containing a curated collection of classical music files in MP3 format. These audio tracks provide background music functionality within the application.

### qss_styles

Is a subdirectory containing Qt stylesheet files that define the visual appearance of the graphical interface. These QSS files provide centralized style management for customizing colors, fonts, spacing, and other visual properties of PySide6 widgets.

### sound_effects

Is a subdirectory containing audio effect files in WAV format. These sound effects provide auditory feedback for user interactions such as button clicks and other interface events.

## config

Is a directory containing application configuration files in JSON format that store settings, preferences, and system parameters. All files here can be customized within the app without modifying the source code.

### `accepted_formats.json`

Is a JSON configuration file that defines the accepted file formats for various file types processed by the application. This dictionary enables the validation of user-uploaded files.

### `assets_paths.json`

Is a JSON configuration file containing a dictionary of file paths to project assets and resources.

### `audio.json`

Is a JSON configuration file that stores audio-related settings including volume levels and audio output preferences.

### `general.json`

Is a JSON configuration file containing general application settings and preferences. This dictionary stores non-audio and non-path specific configurations that affect the overall behavior and user interface of the application.

### `pinned_quizzes_list.json`

Is a JSON file that maintains a list of quiz entries marked as pinned by the user.

### `standard_paths.json`

Is a JSON configuration file containing a dictionary of standard directory paths used throughout the application.
### default_config_copy

Is a backup directory containing default copies of all JSON configuration files. This directory serves as a reference implementation and recovery point, enabling the application to restore default settings.

## src

Is the root directory containing the application's source code, organized following the model-view-design architectural pattern.

### model

Is a directory containing the business logic and data handling modules that form the backend of the application. This layer manages all data processing, transformation, and interaction with configuration and quiz resources.

#### audio_widgets_logic

Is a directory containing modules that manage the logic and data required by audio-related interface widgets. These modules handle the state management and behavior of audio controls presented to the user.

#### configurators

Is a directory containing modules responsible for managing interactions with the application's JSON configuration files. These modules provide an abstraction layer for reading and writing configuration settings throughout the application.

#### data_structure_formatter

Is a directory containing modules that format and transform various data structures used throughout the project. This includes utilities for converting between different string formats, such as transformations from title case to snake_case notation.

#### data_structure_inspector

Is a directory containing modules that analyze and inspect data structures, returning detailed information about their composition and properties. These utilities support validation and debugging operations throughout the application.

#### json_wrapper

Is a directory containing modules that provide a simplified wrapper interface for reading and writing JSON files. This abstraction layer centralizes JSON file operations and error handling across the application.

#### root_dir_quiz_extractor

Is a directory containing the module responsible for extracting and loading quiz information from the project's root directory. This component enables the frontend to access and display available quiz content to users.

#### `translation_handler.py`

Is a Python module that manages multi-language translation functionality throughout the application. This handler provides methods for retrieving localized strings and managing language preferences.

#### quiz_builder

Is a directory containing modules for creating and structuring new quiz entries. These components implement the logic necessary to validate and construct quiz content according to the defined quiz structure specification.

#### quiz_data_handlers

Is a directory containing modules that format quiz data for presentation in the frontend. These handlers transform raw quiz information into structures optimized for visualization and user interaction.

#### `quiz_remover.py`

Is a Python module that manages the removal and deletion of quiz entries from the application. This component handles the logic for safe deletion while maintaining data integrity.

### view_design

Is a directory containing all user interface components and visual design elements that comprise the application's frontend. This layer implements the graphical interface using PySide6 and manages user interaction.

#### custom_animations

Is a directory containing modules that implement custom animation functions for generic PySide6 widgets.

#### custom_widgets

Is a directory containing custom widget class definitions developed specifically for the application's requirements. These reusable components follow consistent patterns and avoid code duplication across the user interface.

#### general_app_configurator

Is a directory containing modules that manage application-wide settings including keyboard event tracking, typography, font selection, and audio output configuration. These modules leverage PySide6 features to control general application behavior.

#### in_quiz

Is a directory containing visual components and interaction logic specific to the quiz display and gameplay experience. These modules manage the presentation and control flow during active quiz sessions.

#### page_design_toolkit

Is a directory containing utility modules that manage common widget behaviors and layout operations safely. These functions handle operations such as layout cleanup with nested widgets and recursive widget expansion.

#### page_manager

Is a directory containing modules that manage application navigation logic and the visual appearance of the navigation bar. These components control page transitions and maintain the overall application flow.

#### pages

Is a directory containing modules that manage the visualization of specific application sections and features. These modules implement distinct pages such as settings, menus, and the quiz creation interface.

## translations

Is a directory containing translation files in multiple formats that enable multi-language support for the application. This directory houses template files, localized translations, and compilation tools necessary for internationalization.

### `CixerQuiz.pot`

Is a gettext template file containing the original English text strings used throughout the application. This template serves as the source for creating translation files in other languages.

### locale

Is a directory containing language-specific subdirectories with compiled translation files. Each language subdirectory contains the corresponding `.mo` and `.po` translation files for that locale.

#### es

Is a subdirectory containing Spanish language translation files in portable object and message object formats.

### translations_builder

Is a directory containing shell scripts that automate the process of building and compiling translation files. These scripts facilitate the creation and maintenance of the multi-language translation system.

#### `mo_compiler.sh`

Is a shell script that compiles message object files from portable object files. This script generates binary translation files that the application uses at runtime for language localization.

#### `po_builder.sh`

Is a shell script that creates or updates portable object translation files. This script generates editable translation files from the template, enabling translators to provide localized content.

#### `pot_builder.sh`

Is a shell script that generates or updates the gettext template file containing all translatable strings. This script extracts translatable strings from the source code to create the master translation template.
